# brainfoundry-nous architecture

*Created 2026-10-25. Replaces the 2026-05-08 system map; drawn from the code in this repository as it is today, nothing planned.*

Diagram: [architecture.mmd](architecture.mmd) (mermaid 11, `flowchart TD`) rendered to [architecture.png](architecture.png).

A brain is six docker services on one box (`docker-compose.yml`: ollama, api, nodeos, ui, public-chat, postgres, plus redis declared but unused by the api). The owner reaches it through the Next.js console, which proxies every call to the FastAPI runtime with the owner key; strangers reach it through the public chat site and the Telegram bot, other brains through the signed federation doors. The runtime assembles each turn from the persona, retrieved memory chunks and session history, routes it to a local Ollama model or a BYOK hosted API, and may run tools by tier (GREEN own-memory reads, YELLOW external reads on standing authorization, RED actions behind a per-call approval). Memory lives in Postgres + pgvector with a privacy level, a public scope and a memory type on every chunk; ingest passes an injection scan, and the private vault feeds local-only chunks that hosted models never see. Governance is the BrainKernel (nodeos) that mints permits, holds proposals and the audit trail, plus the ED25519 identity that signs federation DMs, asks and social posts; three economic registers (substrate attestations, harmonics, compute meter) record what the brain does. Host-side scripts are the hands: the CC bridge drives a headless Claude Code or Codex turn against the brain's API, `gpu-run` rents a GPU per job, and the update, backup, export and vault scripts keep the box.
